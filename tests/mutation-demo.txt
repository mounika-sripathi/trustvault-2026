Mutation test — proof that the test suite actually tests authorization
======================================================================

The challenge says: "We will take one authorisation check out of your code
and run your tests. If they still pass, they were not testing anything."

The check removed for this demonstration: the live-grant condition in the
`documents_select` RLS policy (the authorization engine for document reads).

  BEFORE (production):  using (caller_active() and (is_admin() or owner_id = auth.uid()
                          or (status = 'active' and has_any_grant(id, auth.uid()))))
  MUTATION APPLIED:     using (caller_active() and (is_admin() or owner_id = auth.uid()
                          or status = 'active'))
                         -- the grant check is gone: any active user can now
                            read every active document.

The mutation was applied to the live database, the suite was run, the
original policy was restored, and the suite was run again. Both runs are
reproduced below, unedited. With the check removed, three cross-user tests
fail (viewer listing, IDOR by id, and revoke-immediacy). With the check
restored, all 31 pass.
